### 📚 APRENDIZADOS TÉCNICOS

**Conceito novo 1:** 🛠️ Por que fazer o push inicial?
- **O que é:** Criei a nova branch, porém ela só existe no meu pc. Preciso enviá-la para a nuvem.
- **Por que é útil:**

#### 1. Backup e Segurança (Nuvem)
Com o push a branch já sobe para o github.

#### 2. Visibilidade e Colaboração
No trabalho em um time, todos seus colegas e superiores conseguem ver que você já iniciou o trabalho. Isso evita que duas pessoas tentem fazer a mesma coisa ao mesmo tempo.

#### 3. CI/CD (Automação)
Muitas empresas configuram ferramentas que rodam testes automáticos assim que uma branch nova aparece no servidor. Mesmo que ela esteja vazia, isso valida que o fluxo de integração está funcionando.

**Conceito novo 2:** Documentar Estado Atual
- **O que é:** Documentar o estado atual significa garantir que você sabe exatamente o que o sistema faz hoje e quais são seus comportamentos esperados.
Isso faz parte do processo de QA (Quality Assurance) e Regression Testing. Ao anotar as funcionalidades atuais, você cria um guia para testar no futuro e garantir que a migração não quebrou o que já estava pronto.
- **Por que é útil:**
No desenvolvimento profissional, é comum "consertar uma coisa e quebrar outra". Se você não souber o que estava funcionando antes, pode passar horas tentando descobrir se um erro é novo ou se já existia. Além disso, prints e descrições ajudam muito em Code Reviews para mostrar o "Antes vs Depois".

**Conceito novo 2:** Erro code ERESOLVE
- **O que é:** O famoso "Dependency Hell" (Inferno das Dependências). Conflito de versões das dependencias instaladas, tenho o ESLint 10 mas alguns pacotes não aceitam pois ainda não foram atualizados com essa versão pois ela é nova.
- **Por que é útil:**
No mundo real, projetos têm dezenas ou centenas de dependências.
Saber resolver ERESOLVE significa que você entende:
- versionamento (semver)
- peerDependencies
- compatibilidade entre pacotes

Um júnior que entende o erro:
- verifica versões no package.json
- lê o erro completo
- analisa qual dependência está conflitante
- escolhe a versão correta

- **Como usar:**
#### Opção A: --legacy-peer-deps (Recomendada aqui)
Este comando diz ao NPM: "Ignore os conflitos de peer dependencies e instale assim mesmo, usando o modo de resolução das versões mais antigas do NPM (v6)". É a solução padrão quando estamos migrando projetos e lidando com plugins de linting.
```
npm install react-router-dom zustand framer-motion uuid date-fns firebase lucide-react --legacy-peer-deps
```
```
npm install -D vitest @testing-library/react @testing-library/jest-dom jsdom --legacy-peer-deps
```

#### Opção B: --force
O "soco na mesa". Ele força a instalação sobrescrevendo qualquer conflito. Evite este a menos que o anterior falhe, pois ele pode causar duplicidade de pacotes.
